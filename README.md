# SIDETALK · 사이드톡

Windows 11에서 공식 카카오톡의 보조 인스턴스를 **SIDETALK 전용 Sandboxie Plus 환경**으로 실행하는 한국어 데스크톱 앱입니다.

> **0.1.6 사전 검증 빌드.** 2026-09-16 현재 PC에서 사용자가 보조 계정 로그인과 본계정 동시 송수신을 확인했습니다. 계정 없는 파일/HKCU 격리 시험은 통과했으며, 실제 계정 데이터 분리·알림·재실행 후 로그인과 대화 유지 등은 추가 검증이 필요합니다. [검증 결과](docs/VERIFICATION.md)와 [실환경 검증 절차](docs/ACCEPTANCE.md)를 먼저 읽으세요.

## 실행

저장소에서는 루트의 **`run-local.cmd`를 더블클릭**합니다. 기존 배포본은 재빌드 없이 바로 실행합니다. 직접 실행할 때는 `artifacts/publish/win-x64/Sidetalk.exe`를, 배포 ZIP을 받은 경우에는 압축을 푼 폴더의 `Sidetalk.exe`를 **일반 사용자 권한**으로 실행합니다. 실행 파일이 있는 폴더의 파일을 함께 보관하세요. SIDETALK를 닫아도 카카오톡은 종료되지 않습니다. 보조 카카오톡은 평소 카카오톡 자체 트레이 메뉴로 정상 종료하고, 보조 프로세스가 남을 때만 SIDETALK의 종료 버튼을 사용합니다.

- Windows 11 x64
- 공식 서명이 유효한 카카오톡 (2026-09-16 현재 PC: 26.8.0.5312)
- Sandboxie Plus 1.18.4 x64 (설치본의 사용자 구성요소 5.73.4 / 서명된 드라이버 5.73.2 조합)
- framework-dependent 배포는 .NET 8 Desktop Runtime x64 필요. self-contained 배포는 런타임 포함.

ARM64, 다른 Sandboxie 버전, 포터블/사용자 지정 카카오톡 경로는 이번 빌드의 검증 범위 밖입니다. 기존 설치를 이동하거나 다른 버전을 자동 설치하지 않습니다.

이전 버전에서 업그레이드할 때에는 먼저 이전 SIDETALK가 요청한 명령이 끝났는지 확인하세요. 재시작 복구 기록은 0.1.3부터 생성하므로, 이전 버전이 이미 시작한 기록 없는 명령을 소급 복구하지는 못합니다.

배포본을 교체하기 전에는 SIDETALK와 배포본에 포함된 `tools/IsolationProbe`를 모두 종료하세요. 저장소에서 최신 파일을 반영하는 안정 경로는 이후 빌드에서도 항상 `artifacts/publish/win-x64`로 유지됩니다.

## 초기 설정과 승인된 복구

공식 카카오톡과 Sandboxie Plus 1.18.4가 먼저 설치되어 있어야 합니다. SIDETALK는 설치 프로그램을 실행하거나 카카오톡에 자동 로그인하지 않습니다.

1. 루트의 **`run-local.cmd`를 더블클릭**합니다.
2. 앱이 현재 프로필·전용 box·설치·실제 설정 파일과 상속 규칙을 확인합니다. 준비가 필요하면 복구 영역에 변경 내용과 차단 이유가 표시됩니다.
3. 내용을 확인하고 **복구하고 실행 준비**를 한 번 누릅니다. 같은 범위의 재발도 처리하려면 자동 복구 동의를 선택합니다. 이 동의는 앱에서 해제할 수 있습니다.
4. 앱이 설정과 계획을 백업하고, 필요한 설정만 적용한 뒤 파일과 Sandboxie API를 다시 검사합니다. **실행 준비**가 되면 **보조 카카오톡 실행**을 누릅니다. 실행 확인과 로그인·기기 인증은 기존 공식 카카오톡 흐름을 따릅니다.

승인 범위는 현재 사용자의 전용 환경 준비, 공식 원문과 실제 상속 결과가 확인된 여섯 호환성 템플릿의 전역 선택 제거, 현재 사용자의 `SbieCtrl_AutoRunSoftCompat=n`입니다. 다른 box가 전역 규칙의 영향을 받을 수 있거나 미검토 설정·미완료 명령·실행 중 전용 프로세스가 있으면 자동 변경하지 않습니다. 열린 관리 창이 있으면 확인된 현재 사용자·세션의 관리 UI 종료 대상도 승인 내용에 포함됩니다. 서비스·드라이버·카카오톡은 복구를 위해 종료하지 않습니다.

전용 프로필·소유 식별자·계정·대화 데이터와 기존 작업 기록을 보존합니다. 정상 상태에서는 설정을 다시 쓰거나 백업을 반복 생성하지 않습니다. 실패나 경합 시 전체 백업을 현재 INI 위에 덮어쓰지 않으며, 기록을 보존하고 실행을 차단합니다. 자세한 범위는 [설정 안내](docs/SETUP.md)를 참고하세요.

**처음부터 메인 프로필/대화가 보이면 로그인하지 말고 검증을 중단하세요.** 계정 데이터를 복사하거나 보안 예외를 추가해 계속 진행하지 마세요.
## 일상적인 실행 순서

처음 설정을 마친 뒤에는 다음 순서로 사용합니다.

1. 공식 카카오톡이 설치된 PC에서 루트의 `run-local.cmd`를 더블클릭합니다. 본계정 카카오톡은 켜 둬도 됩니다.
2. SIDETALK가 창을 열면서 상태를 자동 확인합니다. **실행 준비**가 표시되면 약 4초를 기다리지 않고 곧바로 다음 단계로 진행해도 됩니다. 이후 상태는 약 4초마다 자동으로 다시 확인되며, 필요할 때 **상태 새로 확인**을 눌러도 됩니다.
3. 상태가 실행 준비일 때 **보조 카카오톡 실행**을 누릅니다.
4. 보조 카카오톡 창에서 보조 계정으로 로그인합니다. 프로세스가 보인다는 사실만으로 로그인·인증·송수신 성공을 판정하지 않습니다.

## 실행 상태와 종료

- 우상단 상태 배지는 전용 box의 현재 상태를 요약합니다. **실행 중**은 전용 환경의 프로세스가 확인됐다는 뜻입니다.
- 실행 중 화면에는 **현재 격리 설정 확인됨 · 시작 당시 적용 규칙은 확인 불가**가 표시될 수 있습니다. 현재 설정이 잘못됐다는 뜻이 아니라, Sandboxie API로 이미 시작된 프로세스가 시작 순간 어떤 규칙을 적용받았는지 소급 증명할 수 없다는 뜻입니다. 로그인 여부, 실제 송수신, 알림도 자동 판정하지 않습니다.
- 이 확인 한계는 정상 종료 후 다시 실행해도 없어지지 않습니다. 카카오톡 자체 트레이 메뉴로 정상 종료한 뒤 SIDETALK에서 **상태 새로 확인**을 눌러 전용 box가 비었고 현재 격리 설정이 확인됐는지 확인한 뒤 다음 실행을 준비합니다. 새로 실행한 프로세스에도 시작 당시 적용 규칙은 확인 불가로 표시됩니다.
- 트레이 종료 후에도 보조 프로세스가 남고 **보조 카카오톡 강제 종료** 버튼이 활성화된 경우에만 이 버튼을 사용합니다. 이 동작은 해당 전용 환경 전체에 `/terminate`를 보내므로 카카오톡과 보조 프로세스를 강제 종료하며 미저장 작업이 손실될 수 있습니다. 실행·종료가 차단된 상태에서는 버튼도 비활성화되므로, 진단에 표시된 설정 차단 사유를 확인하고 설정을 복구한 뒤 새로고침합니다.
- 실행 요청 후 소속 프로세스가 확인되어야 실행 상태를 표시합니다. 명령 성공 코드만으로 판단하지 않습니다.
- 명령 시간이 초과되거나 SIDETALK가 종료돼도 작업 기록은 남습니다. 재시작 시 PID·생성 시각·실행 경로를 확인하며, 이전 명령의 종료와 새로 조회한 전용 프로세스 상태가 함께 확인돼야 새 명령을 허용합니다. PID가 재사용되면 그 프로세스를 이전 명령으로 취급하지 않습니다.
- 프로세스 생성 전 기록과 PID 저장 사이에 중단됐다면, 같은 설치의 Start.exe 후보가 없음을 확인한 뒤 박스를 다시 조회합니다. 다른 Sandboxie 명령이 실행 중이거나 조회가 불확실하면 계속 차단합니다. 다른 프로세스를 종료해 복구하지 않습니다.
- 최초 작업 기록 폴더 생성 중 중단돼 잠금 파일이 빠졌다면 일반 GUI 새로고침에서 잠금을 복구한 뒤 기록을 검증합니다. 미완료·손상 기록을 지우거나 완료로 간주하지 않습니다. 읽기 전용 진단은 잠금 파일도 만들지 않습니다.
- 저장된 파일/레지스트리는 유지합니다. 자동 삭제·초기화·복구/호스트 반출 기능은 제공하지 않습니다.
- 설정 드리프트가 발견되면 종료도 차단합니다. 특히 자동 삭제가 켜진 환경을 종료해 데이터가 사라지는 상황을 방지합니다. 전역 설정을 바꿔 검사기를 통과시키지 마세요.

## 저장 위치

| 항목 | 위치 |
|---|---|
| 설정 복구 내역·백업·동의 | `%LOCALAPPDATA%\SIDETALK\setup-recovery` |
| 명령 작업 기록 | `%LOCALAPPDATA%\SIDETALK\command-journal` (완료된 기록도 보존) |
| SIDETALK 소유 정보 | `%LOCALAPPDATA%\SIDETALK\profile.json` |
| 보조 환경 파일 | `%LOCALAPPDATA%\SIDETALK\Boxes\SideTalk_<고유 ID>` |
| 보조 환경 레지스트리 | Sandboxie가 전용 환경용으로 만든 별도 하이브 |
| 설정 내보내기/진단 | 사용자가 선택한 새 파일 |

최초 프로필은 같은 폴더의 임시 파일에 완전히 기록한 뒤 기존 파일을 덮어쓰지 않는 이름 변경으로 반영합니다. 중단된 임시 파일과 손상된 기존 프로필은 자동 삭제·덮어쓰기하지 않습니다.

프로필 파일을 삭제하면 기존 환경을 자동으로 다시 연결하지 않습니다. 기존 환경이나 데이터가 있어도 자동 삭제하지 않습니다. 사용자 데이터·레지스트리·대화 내용은 진단에 수집하지 않습니다. 진단에는 설치 경로, 사용자 폴더 경로, 버전, 전용 프로세스 PID가 포함되므로 공유 전에 확인하세요.

## 빌드와 검증

PowerShell 7, .NET SDK 8.0.400 이상(8.x), 저장소 루트에서 실행합니다.

```powershell
# 개발 중 코드 검증 (배포 앱을 켜 둔 채 실행 가능)
pwsh -File scripts/verify.ps1

# 복구 UI 변경 시 합성 WPF 검사도 포함
pwsh -File scripts/verify.ps1 -UiChecks

# self-contained 패키지 생성·기존 배포본 교체 (.NET 런타임 포함)
pwsh -File scripts/build.ps1 -SelfContained

# framework-dependent 패키지 생성·교체 (.NET 8 Desktop Runtime 필요)
pwsh -File scripts/build.ps1
```

`verify.ps1`는 Release 앱 빌드·자체 콘솔 안전성 테스트·IsolationProbe 빌드만 수행합니다. 기존 배포 폴더·ZIP·사용자 설정을 변경하지 않으며, 실행 중인 배포본을 검사해 검증을 막지 않습니다. `bin/obj`와 테스트용 `artifacts/tests`에는 빌드·합성 검사 결과가 생깁니다. 실제 빌드 출력이 잠겼다면 dotnet이 출력한 파일 경로와 오류를 확인하세요. 스크립트가 프로세스를 종료하지는 않습니다. `-UiChecks` 결과는 매번 새 임시 폴더에 생성하고 위치를 출력합니다. 두 스크립트는 `bin/obj`를 공유하므로 동시에 실행하지 마세요.

`build.ps1`는 같은 검증을 한 번 수행한 뒤 각 프로젝트를 `win-x64`와 선택한 런타임 모드로 복원·publish합니다. 일반 빌드 결과만으로 RID별 publish를 생략하지 않습니다. README와 docs를 포함한 ZIP과 SHA-256을 staging에서 준비한 뒤 `artifacts/publish/win-x64`로 반영합니다. 빌드·테스트·publish·압축 실패 시 기존 배포본과 ZIP을 유지하고, 교체 실패 시 롤백합니다. 경로 경계·reparse point 검사, 실행 중 출력 보호와 publish lock도 유지합니다. 롤백까지 실패하면 원래 오류·롤백 오류·보존 경로를 출력하며 staging을 남깁니다. 버전별 ZIP은 `artifacts`에 계속 보관합니다.

패키징 전에는 해당 배포본의 SIDETALK와 `tools/IsolationProbe`를 정상 종료해야 합니다. `build-local.cmd`는 기존대로 self-contained 패키징 후 앱을 열며, `build-local.cmd -NoLaunch -NoPause`는 패키징만 합니다. `run-local.cmd`는 기존 배포본을 바로 열고 배포본이 없을 때만 패키징합니다. 단순 코드 검증에는 위 `verify.ps1`를 사용하세요.

각 단계는 경과 시간과 실패 단계를 출력합니다. 종료 코드 `0`은 성공이며, 다음 코드는 CMD 진입점에서도 전달됩니다.

| 종료 코드 | 실패 단계 |
|---|---|
| 10 / 11 / 12 / 13 | 앱 빌드 / 콘솔 안전성 테스트 / 시험 도구 빌드 / 합성 WPF 검사 |
| 20 | 패키징 사전 검사·잠금·실행 중 출력 보호 |
| 21 / 22 / 23 | 앱 publish / 시험 도구 publish / 문서 복사·버전 확인 |
| 30 | ZIP·SHA-256 생성 |
| 40 / 41 | 배포 교체(롤백 완료 또는 교체 전 차단) / 교체와 롤백 모두 실패 |

진입점·도구 실행·스크립트 로딩 오류는 일반 비영 종료 코드로 반환될 수 있습니다. 이전 검증 통과 기록으로 현재 안전성 테스트를 생략하는 옵션은 없습니다.
교체 도중 PowerShell 강제 종료나 전원 장애가 발생하면 자동 복구되지 않을 수 있습니다. 이때 기존 배포본은 `artifacts/.publish-<고유 ID>/previous-win-x64`에 남을 수 있으므로, 임시 폴더를 삭제하지 말고 기존 파일과 반영 상태를 먼저 확인하세요.

스크립트가 출력한 배포 폴더에서 자체 GUI 렌더링과 읽기 전용 진단(카카오톡 실행 없음):

```powershell
.\Sidetalk.exe --render C:\temp\sidetalk.png
.\Sidetalk.exe --diagnose C:\temp\sidetalk-diagnostics.json
```

출력 파일의 상위 폴더를 먼저 준비하고 진단 파일에는 새 이름을 사용하세요. `--diagnose`, `--render`, `--render-small`, `--render-setup`은 복구 동의가 있어도 설정 변경·자동 복구·카카오톡 실행을 하지 않습니다. 일반 GUI의 설정 변경은 최초 승인 또는 저장된 동일 범위의 자동 복구 동의가 필요하며, 카카오톡 실행·종료는 별도의 명시적 조작이 필요합니다.

## 계정 없는 시험 도구

[시험 도구 사용법](docs/ISOLATION-PROBE.md)에 따라 사용자 승인 후 고유 시험 파일 4개와 HKCU 시험 키를 만듭니다. 박스 내부 소속·저장 경로 검사, 호스트 값 숨김, 별도 쓰기, 모든 프로세스 종료 후 재실행 유지, 호스트 원본 유지까지 확인합니다. 결과는 작업 폴더와 전용 저장소에 보존하며 자동 삭제하지 않습니다.

Sandboxie의 프로그램 호환성 창은 SIDETALK의 확인창과 다릅니다. 전역 호환성 템플릿을 적용하면 SIDETALK가 검토되지 않은 상속 규칙으로 차단할 수 있습니다. 다른 환경에 필요한 규칙은 자동으로 제거하지 않습니다.
## 구현 범위

C# / .NET 8 / WPF, 외부 NuGet 의존성 없는 앱·콘솔 테스트. 공식 설치 파일의 Authenticode 서명을 확인하고, Sandboxie의 읽기 전용 API와 `Start.exe`의 명시적 box 명령을 사용합니다. 승인된 설정 준비·복구에 한해서 별도로 검증한 공식 `SbieIni.exe`를 사용합니다. 카카오톡 패치, 자체 주입·후킹, 뮤텍스/핸들 해제, 인증 우회, 이미지 이름으로 종료하는 코드가 없습니다.

1.18.4 공식 기본 템플릿은 출처·내용·값 순서를 고정 기준과 대조합니다. 명시적으로 추가한 전역 설정과 자동 확장된 기본 규칙을 구분하며, 사용자 재정의·추가 템플릿·알 수 없는 예외는 계속 차단합니다. 기준 데이터의 출처와 재생성 방법은 [Sandboxie 자료 안내](docs/third-party-sandboxie.md)에 있습니다. 고정 자료 회귀 검사와 실제 설치의 API 반환값 대조를 모두 통과했습니다. 계정 없는 파일/HKCU 시험도 통과했습니다. 사용자가 실제 보조 계정 로그인·동시 송수신을 확인했으며, 계정 데이터 분리·영속성과 WebCache COM/IPC 연결 검사는 남아 있습니다.

공식 앱 및 Sandboxie는 배포본에 포함하지 않습니다. SIDETALK는 Kakao 또는 Sandboxie의 공식 제품이 아닙니다.
